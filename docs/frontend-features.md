# PolLens Frontend — Feature Inventory

> **Historical snapshot (phase 2 of the reconciliation, before the backend
> existed).** Much of it is out of date: mocked sign-in, IndexedDB storage, the
> 8-species catalog, the missing `/dataset` page and the in-browser mock model
> have all been replaced. Use `system-spec.md` and `../api/CLAUDE.md` for the
> current state; keep this file only as the record the reconciliation was
> built from.

Extracted directly from `app/PolLens/` source (Next.js App Router, React 19,
Tailwind, Recharts, jsPDF). No backend exists yet — this is a frontend-only
build with a mock inference service, browser storage in place of a database,
and no `app/api/` route handlers. Every "expected API" note below is either a
`TODO(backend)` comment already in the source or an inference from the shape
of the mock/local functions the UI calls.

| Module | Feature/Component | Description | Expected API Calls or Data |
|---|---|---|---|
| **Auth** | Sign-in page (`app/page.tsx`) | Landing/login screen. Split hero (product pitch, "Classes tracked / Model / Access" stat strip) + sign-in card. No route guard exists elsewhere in the app — any page can be loaded directly without a session. | None itself; delegates to `SignInForm`. |
| **Auth** | `SignInForm` component | Mocks Google's account chooser. Two-step UI: (1) "Continue with Google" button, (2) an email field standing in for the account picker. **Form fields:** single `email` text input (type="email"), validated with regex `^[^\s@]+@[^\s@]+\.[^\s@]+$`. Live preview shows the institution/account name derived from the email as the user types. **State:** local `choosing` (bool, which step is shown), `email` (string). On submit calls `updateSettings({ email })` (writes to localStorage) then `router.push("/dashboard")`. | No real OAuth call. `TODO(backend)`-style comment in `lib/account.ts`: real Google sign-in will provide the email from an ID token (and `hd` claim for institution) instead of manual entry — expected shape is a session object `{ email: string }`. |
| **Layout/Nav** | `Sidebar` component | Global nav rail (desktop) / top bar + drawer (mobile). Links: Dashboard, Analyze specimen (`/upload`), Report (`/reports`), Pollen map (`/map`), Allergen reference (`/dataset` — **note: this route is not implemented in the codebase**, no `app/dataset` folder exists). Account card at the bottom links to `/settings`, shows name + initials derived from the signed-in email via `useSettings()`/`accountName()`/`getInitials()`. **State:** `menuOpen` (bool, mobile drawer). Reads `pathname` via `usePathname()` to highlight active section. | Reads session via `useSettings()` (localStorage-backed hook, `lib/settings.ts`), not an API call. |
| **Dashboard** | Dashboard page (`app/dashboard/page.tsx`) | Landing screen after sign-in. "Start new analysis" CTA linking to `/upload`, quick stats, historical pollen chart, and the same saved-reports table used on `/reports`. Server component that passes seed `dashboardStats` / `historicalPollenCounts` as initial props. | None directly; composes `DashboardStats`, `PollenCountChart`, `ReportsWorkspace`. |
| **Dashboard** | `DashboardStats` component | 4 stat cards: Specimens analyzed, Allergen classes, This week (new IDs), Avg. confidence. **State:** `stats` initialized from server-seeded props, then recomputed client-side once `listReports()` resolves (merges IndexedDB-saved reports with seed data). | `listReports()` (local, `lib/store.ts` — reads IndexedDB `reports` store + seed `specimens[]`). No network call. Expected future shape per code comments: `GET /api/reports` returning `Specimen[]`. |
| **Dashboard** | `PollenCountChart` component | Recharts line chart of monthly grain counts per species (Poaceae, Betula, Alnus, Corylus, Quercus), with a 6/12-month range toggle. **State:** `range` (6 or 12, local). Data comes from `historicalPollenCounts` (static seed array in `lib/data.ts`) — described in code as "a separate real-world dataset (continuous monthly air-monitoring measurements)". | No API call yet; static mock data. Implied future data need: a monthly aggregation endpoint returning `{ month, [genus]: count }[]` per species, independent of individual specimen records. |
| **Analyze/Upload** | Analyze specimen page (`app/upload/page.tsx`) | Wraps `AnalyzeWorkspace`. | — |
| **Analyze/Upload** | `AnalyzeWorkspace` component | Multi-image batch upload + collection metadata entry, then runs mock inference per image. **Form fields:** file input (multiple, `accept="image/*"`, drag-and-drop supported); Location (text); Researcher (text, defaults to account-derived name); Date collected (date, required to enable Analyze); Time collected (time, optional); Weather condition (select: Sunny/Partly cloudy/Overcast/Rainy/Windy); Temperature °C, Humidity %, Wind km/h (number inputs, nullable). **State:** `items: BatchItem[]` (id, File, object URL, status: pending/analyzing/analyzed, detections), `selectedId`, `location`, `researcher`, `collectedDate`, `collectedTime`, `weather`, `isAnalyzing`, `isDragging`, `hasPendingDraft` (warns if an unsaved draft exists from a previous visit, loaded via `getDraft()`). On submit, each file is sent through `analyzeSpecimen(file)` sequentially, then the batch is written to an IndexedDB "draft" via `saveDraft()` and the user is routed to `/upload/result`. | `analyzeSpecimen(file: File)` — currently a deterministic **mock** (`lib/analysis.ts`) that seeds a PRNG from the file's name/size/lastModified, fabricates 2–4 species with grain boxes, and resolves after ~1.4s. `TODO(backend)` comment specifies the real contract: **POST the image to a Roboflow inference endpoint**; response shape expected is Roboflow's standard `{ predictions: [{ class, confidence, x, y, width, height }] }` in **pixel, center-based** coordinates, to be mapped to normalized top-left `BoundingBox { x, y, width, height }` via `{x:(p.x-p.width/2)/imgW, y:(p.y-p.height/2)/imgH, width:p.width/imgW, height:p.height/imgH}`. Also calls `fetchWeather(location)` (currently always resolves `null`); `TODO(backend)`: call an OpenWeather-style provider and map its response onto `WeatherConditions { condition, temperatureC, humidityPct, windKph }`. |
| **Analysis Result** | Analysis result page (`app/upload/result/page.tsx`) | Wraps `AnalysisResultWorkspace`; back-link to Analyze. | — |
| **Analysis Result** | `AnalysisResultWorkspace` component | Review/edit screen for a just-run analysis before it becomes a saved report. Left: per-species detection rows (grain count, avg. confidence, risk badge) with click-to-highlight. Right: `SpecimenImageViewer` (boxed slide image) + per-slide Notes textarea. Bottom: same Collection details fields as Analyze (Location, Researcher, Date, Time, Weather/Temp/Humidity/Wind), editable. Discard (with confirm step) and Save report actions. **State:** `draft` (loaded from IndexedDB via `getDraft()`; `undefined`=loading, `null`=none), `imageUrls` (object URLs per slide), `selectedId`, `highlighted` (species filter for the overlay), `notes` (per-slide, keyed by slide id), `location`, `researcher`, `collectedDate`, `collectedTime`, `weather`, `isSaving`, `confirmingDiscard`, `hydrated`. Debounced (400ms) auto-save writes every edit back into the draft via `saveDraft()`. | `getDraft()` / `saveDraft()` / `clearDraft()` (local IndexedDB, `lib/store.ts`). On "Save report": `saveReport(input, images)` — persists a `Specimen` record (with minted `sampleId` like `PLN-2026-NNNN`) plus per-slide image blobs to IndexedDB, then redirects to `/reports?saved={sampleId}`. Code comment specifies the eventual backend contract: `POST /api/reports` (multipart, images included) returning the created row so the sample ID comes from the DB instead of being client-minted. |
| **Analysis Result** | `SpecimenImageViewer` component (shared, also used in Reports) | Renders a slide image with per-grain bounding-box overlays (from `DetectedGrain[]`, normalized 0–1 coordinates), a species filter-chip row, and a "not stored"/"no boxes recorded" fallback state. Read-only display component driven by props (`imageUrl`, `fileName`, `grains`, `detections`, `selectedSpeciesId`, `onSelectSpecies`); no own network/storage calls. | None (pure presentational; boxes come from the parent's already-loaded detection data). |
| **Reports** | Reports page (`app/reports/page.tsx`) | Wraps `ReportsWorkspace` in a `Suspense` boundary (uses `useSearchParams`). | — |
| **Reports** | `ReportsWorkspace` component | Loads the merged report list (IndexedDB-saved + seed) client-side and passes it, plus URL params `saved` (highlight id) and `q` (initial search text, used when arriving from the Pollen map's "view reports from X" link), into `ReportsTable`. | `listReports()` (local). |
| **Reports** | `ReportsTable` component | Filterable/searchable table (desktop) / card list (mobile) of all saved reports, with multi-select + bulk PDF/Excel export. **Filters:** search (sample id, location, pollen, date), Status (All/Pending/Needs Review/Completed), Location, and collection date range. **State:** `filters {query, status, location, from, to}`, `picked: Set<sampleId>`, `building` (PDF/Excel generation in progress). Row click navigates to `/reports/[sampleId]`; selection persists across filter changes. | `downloadSelectionReportPdf({ reports })` (`lib/pdf.ts`, client-side jsPDF) and `exportReportsXlsx` (`lib/export.ts`). Only Completed reports can be exported; Pending and Needs Review are excluded until completed. |
| **Report Detail** | Report detail page (`app/reports/[sampleId]/page.tsx`) | Server component; awaits the dynamic `sampleId` route param and renders `ReportDetail`. | — |
| **Report Detail** | `ReportDetail` component | Full single-report view: header (sample id, status badge, Download PDF button), Collection details (date, time, location, researcher, weather/temp/humidity/wind), combined Results summary (total grains, pollen types, avg. confidence, slide count), and one block per slide (its own detection list + `SpecimenImageViewer` + researcher's note). **State:** `report` (undefined=loading/null=not found/`Specimen`), `imageUrls`, `highlighted` (per-slide species filter, keyed by slide id), `downloading`. | `getReport(sampleId)`, `getReportImageUrls(sampleId)`, `getReportImageBlobs(sampleId)` (all local IndexedDB reads, `lib/store.ts`). "Download PDF" calls `downloadReportPdf(report, blobs)` (`lib/pdf.ts`, purely client-side rendering — no network call). |
| **Pollen Map** | Pollen map page (`app/map/page.tsx`) | Wraps `PollenMap`. | — |
| **Pollen Map** | `PollenMap` component | Interactive choropleth of the Philippines: province view drilling into a province's towns, shaded by grain counts, filterable by species/region/search, with pan-zoom (`useMapZoom` hook), a ranked "Hotzones" side panel, and PDF report generation scoped to a place or a filtered set of places. **Form/filter fields:** species select ("All pollen" + each of the 8 catalog species), free-text place search, Region select (country view only, 17 PSA regions), Sampled/All toggle. **State:** `reports`, `provinces` (GeoJSON), `towns` (per-province GeoJSON, lazy-loaded), `scope` (country vs. one province), `species`, `filters {query, region, show}`, `selected` (place key), `hovered`, `building` (which report PDF is generating), plus zoom/pan view state from `useMapZoom`. | `fetch("/geo/provinces.json")` — static file, ~88 provinces/districts. `fetch("/geo/municipalities/{psgc}.json")` — static per-province town boundaries, fetched lazily on drill-in. `listReports()` (local IndexedDB+seed). "Generate report" buttons call `downloadLocationReportPdf(...)` (`lib/pdf.ts`, client-side, no network). Comment in `lib/geo.ts` notes boundary data ships with the app specifically so "a thesis figure should not depend on a third-party endpoint staying up" — i.e., no live geocoding API is used or planned here. |
| **Pollen Map** | `useMapZoom` hook | Pan/zoom/drag gesture state for the map SVG (wheel zoom, drag-to-pan, pinch, fit-to-bounds). Pure client-side interaction state (`view: {x,y,k}`, `dragging`, etc.) — no data fetching. | None. |
| **Settings** | Settings page (`app/settings/page.tsx`) | Wraps `SettingsWorkspace`. | — |
| **Settings** | `SettingsWorkspace` component | Three sections: **Profile** (avatar/initials, derived name, signed-in email, institution-detection explainer — all read-only, derived from the email); **Data & storage** (counts: saved reports / slide images / approx. size; Export JSON backup, Export CSV for analysis buttons; "Clear locally saved reports" destructive action with a confirm step, seed records excluded); **Account** (Sign out — clears the local session and redirects to `/`). **State:** `reports`, `storage {reportCount, imageCount, approxBytes}`, `confirmingClear`, `clearing`. | `listReports()`, `getStorageSummary()`, `clearAllReports()` (all local IndexedDB, `lib/store.ts`). `exportReportsJson(reports)` / `exportReportsCsv(reports)` (`lib/export.ts`) — build and download a JSON/CSV file client-side from in-memory data; explicitly excludes slide images ("download a report's PDF for those"). `resetSettings()` clears the localStorage session key. No network calls anywhere on this page. |
| **Shared data/service layer** | `lib/store.ts` — report persistence | IndexedDB (`pollens` DB, v2) wrapper with 3 object stores: `reports` (keyed by `sampleId`), `images` (keyed by `slideId`, indexed by `sampleId`), `drafts` (single record, key `"current"`). Exposes `listReports`, `getReport`, `getReportImageUrls`, `getReportImageBlobs`, `saveReport`, `saveDraft`/`getDraft`/`clearDraft`, `deleteReport`, `getStorageSummary`, `clearAllReports`, `isSeedReport`. | Explicit migration map is documented in the file's header comment: `listReports()` → `GET /api/reports`; `getReport(id)` → `GET /api/reports/:id`; `saveReport(input)` → `POST /api/reports` (multipart, images included). Seed records from `lib/data.ts` are always merged in as read-only history alongside whatever the backend/IndexedDB holds. |
| **Shared data/service layer** | `lib/analysis.ts` — inference/weather service seam | `analyzeSpecimen(file)` and `fetchWeather(location)` — the intended integration points for the real model and weather provider (see Analyze/Upload row above for the exact expected request/response mapping). `NewReportInput`/`NewSlideInput` types define the payload shape a save operation sends downstream. | See `analyzeSpecimen`/`fetchWeather` notes above (Roboflow inference endpoint; OpenWeather-style provider). |
| **Shared data/service layer** | `lib/account.ts` — identity derivation | Pure functions deriving a display name/institution from an email address (`domainOf`, `institutionFromEmail`, `personFromEmail`, `accountName`, `getInitials`). No stored profile — the account is *only* the email. | `TODO(backend)`: once Google sign-in is real, the email comes from the ID token, and the `hd` (hosted domain) claim gives the institution directly. |
| **Shared data/service layer** | `lib/settings.ts` — signed-in session | `useSettings()` hook (via `useSyncExternalStore`) reading a `Settings { email: string }` object from `localStorage` key `pollens.settings.v1`; `updateSettings(patch)`, `resetSettings()`. | Not an API; will become "the session" once real auth lands, per in-file comment — no consumer of `useSettings()` should need to change. |
| **Shared data/service layer** | `lib/geo.ts` — location matching, choropleth math | Parses free-text `location` strings ("Town, Province") to match against PSGC boundary features; builds quantile-based choropleth color scales; projection/zoom/pan math for the SVG map. Ships static boundary files (`public/geo/provinces.json`, `public/geo/municipalities/*.json`, sourced from `faeldon/philippines-json-maps`). | Static file fetches only (see Pollen Map row); no live geocoding service. |
| **Shared data/service layer** | `lib/export.ts` — bulk export | `exportReportsJson(reports)` (full JSON backup, `formatVersion: 1`) and `exportReportsCsv(reports)` (long-format, one row per detected species per slide — 20 columns including sample_id, dates, location, researcher, weather fields, species code/genus/common name/risk, grain_count, avg_confidence, notes). Both trigger a client-side `Blob` download. Deliberately excludes slide images. | None — pure client-side file generation from already-loaded `Specimen[]`. |
| **Shared data/service layer** | `lib/pdf.ts` — PDF generation | `downloadReportPdf` (single report), `downloadSelectionReportPdf` (multiple chosen reports), `downloadLocationReportPdf` (place/region-scoped report from the map). Builds real vector PDF (jsPDF) mirroring the on-screen report layout, including grain boxes drawn as vector rectangles over embedded slide images. | None — entirely client-side rendering from data already loaded via `lib/store.ts`/`lib/geo.ts`. |
| **Shared data/service layer** | `lib/data.ts` — domain types & seed dataset | Central type definitions (`Species`, `SpeciesId`, `GrainPrediction`, `DetectedGrain`, `SpecimenDetection`, `WeatherConditions`, `Specimen`, `SpecimenSlide`, `ReportRow`, `AllergenClass`, `DashboardStats`, `MonthlyPollenCount`) plus the 14-record seed `specimens[]` dataset (Quezon-province localities, "today" fixed at `2026-07-29`), an 8-species `speciesCatalog` (Poaceae, Betula, Alnus, Corylus, Quercus, Ambrosia, Pinus, Artemisia — each with genus, common name, code, season, risk level, color), and derived aggregation helpers (`aggregateGrainPredictions`, `aggregateSlideDetections`, `computeDashboardStats`, etc.). This is the single source of truth every screen reads from; no fetch involved. | Defines the exact data shapes a real backend would need to produce/accept — e.g. `Specimen { sampleId, collectedAt, location, slides: SpecimenSlide[], weather, researcher, status }` and `SpecimenSlide { id, fileName, detections: SpecimenDetection[], grains?: DetectedGrain[], notes }`. |
