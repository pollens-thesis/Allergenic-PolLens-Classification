# System Spec — Paper vs. Frontend Reconciliation

Phase 3 output of the reconciliation process described in `docs/reconciliation-plan.md`.
Produced by comparing `docs/paper-features.md` (extracted from the thesis proposal PDF
alone) against `docs/frontend-features.md` (extracted from `app/PolLens/` alone).

Per the root `CLAUDE.md` precedence rule: for **implementation details** (API contracts,
data shapes, field names, user flows) the **frontend is authoritative**; for **scope,
objectives, and terminology** the **paper is authoritative**. The "Backend Impact" column
below follows that rule — it does not recommend changing the frontend to match the paper.

## Notes: Unresolved Conflicts (flagged, not resolved)

- **Backend language/architecture is internally inconsistent in the paper, and also conflicts with the actual repo layout.** The paper's Backend/Data Layer section says "Backend API (Python)," while its Infrastructure/Deployment section says the backend is Next.js serverless API routes co-hosted with the frontend on Vercel with "no separate hosting instance." The actual repo has a standalone top-level `api/` directory being developed independently from `app/PolLens/` (per root `CLAUDE.md`), which doesn't cleanly match either description. This needs a team decision (language/framework, and whether it's co-hosted with the frontend or a separate service) rather than being inferred from either paper section.
- **Map feature divergence (pins+MapTiler vs. choropleth+static data) is large enough to double-check with the adviser.** The frontend's choice to ship a choropleth with bundled static GeoJSON instead of pin markers on live MapTiler tiles is deliberate and well-justified in code comments (avoiding a third-party dependency for a thesis artifact), but it's a significant enough change from the paper's described feature that it's worth confirming this was an intentional adviser-approved revision rather than an interim placeholder that was never reconciled back to the paper.
- **Paper's internal light/dark theme inconsistency** (already noted in `docs/paper-features.md`): Section 5.1.3's UI mockups describe a light theme with green accents, while Sections 5.1.1.2–5.1.1.3 specify a dark-mode map and dark-mode bounding-box visibility. This is a paper-only inconsistency, not a paper-vs-frontend conflict, but is repeated here since it affects how "Unchanged" is judged for visual/theme-related rows.
- **`Analysis Lab — Pending Queue` (multi-sample resumable queue) has no frontend counterpart at all.** Only a single current draft is supported. Unclear whether concurrent multi-sample pending sessions are still required scope, or whether the single-draft model is the accepted revision.
- **`Archived Session History` (dedicated archive with year-over-year comparison) has no frontend counterpart at all.** Historical/seed reports are merged into the ordinary Reports list with no distinct archive UI, search-by-time-period, or comparison tooling. Unclear whether this is still required scope.
- **Excel export from the paper is entirely absent**, replaced by CSV/JSON. Whether CSV satisfies the original requirement, or Excel (.xlsx) generation is still needed, is unresolved.
- **The paper's `User.role` field has no frontend counterpart** — nothing in the Settings, Sidebar, or account-derivation code references roles or permission tiers. Unclear if role-based access control is still in scope.
- **No route/session guard exists anywhere in the frontend** (any page can be loaded directly without signing in). This was a reasonable placeholder while there was no backend; real OAuth now exists (see the Google OAuth row above), so this is no longer a "no backend yet" gap — it's an open frontend decision (middleware vs. per-page) that needs to be made and built, just not by a backend session per the root CLAUDE.md's Frontend Integration-Point Edits exception.
- **Sidebar links to an `/dataset` ("Allergen reference") route that does not exist in the codebase** — an internal frontend inconsistency, not a paper-vs-frontend conflict, but worth knowing about since it suggests the current information architecture is not fully finalized on the frontend side either.
- **Taxonomic scope (8-species catalog) has not been cross-checked against the actual UPLB dataset/ML artifacts** in this pass — only against the paper's textual scope description. Confirming the frontend's species list matches the dataset actually used for model training is outside what either source document in this reconciliation could verify.
